# デートBot — エクスポート機能 要件定義 v1（MVP）

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-10-06 |
| ステータス | **MVP 実装済み（ローカル）** |
| 対象 | Phase B Web UI（`app/`） |
| 前提 | [date_bot_ui_phase_b.md](./date_bot_ui_phase_b.md) の候補履歴（`plan_history`） |

---

## 1. 目的

ユーザーが **候補履歴の1セット（案3つ＋条件）** を、LINE や Instagram DM などに **手動で貼り付けやすいプレーンテキスト** としてクリップボードにコピーできるようにする。

- Bot からの自動 DM 送信は行わない
- チャットログはエクスポートに含めない
- まず **ローカル開発環境** で完成させ、Hugging Face Spaces は後続

---

## 2. スコープ

### 2.1 やること（MVP）

| # | 内容 |
|---|------|
| E1 | UI に **エクスポート** ボタンを置き、ユーザーが **どのセットをコピーするか選ぶ** |
| E2 | 選んだ1セットから **整形済みテキスト** を生成し **クリップボードにコピー** |
| E3 | コピー成功時、短いフィードバック（例: 「コピーしたよ」）を UI で表示 |
| E4 | エクスポート実行を **サーバー側にログとして記録**（同一セッション内） |

### 2.2 やらないこと（MVP）

| # | 内容 |
|---|------|
| X1 | LINE Messaging API / 公式 Bot による **自動 push** |
| X2 | Web Share API 必須化、Instagram **自動 DM** |
| X3 | 送信前プレビュー・本文編集 UI |
| X4 | チャット（`messages`）のエクスポート |
| X5 | 複数セットの一括エクスポート |
| X6 | 画像・PDF・URL 短縮・地図リンクの自動付与 |
| X7 | エクスポートログの DB 永続化・管理画面 |

---

## 3. 確定した product 決定（チェックリスト反映）

| 項目 | 決定 |
|------|------|
| エクスポート単位 | **1セット**（`plan_history` の1エントリ）。**チャットは含めない** |
| 送信の意味 | **テキストのクリップボードコピーのみ**（ユーザーが LINE / IG 等に自分で貼る） |
| Instagram 自動 DM | **対象外（諦める）** |
| LINE | **Messaging API / Bot（C）も Web Share 必須（B）も使わない**。コピーのみ。LINE へはユーザーが貼り付け |
| プレビュー・編集 | **不要** |
| ユーザー提示の「本文テンプレ見本」 | **なし**（固定の挨拶文テンプレは設けない。§5 の整形ルールのみ） |
| 送信ログ | **残す**（§6） |
| デプロイ | **まずローカル**（`uvicorn`） |

## 4. エクスポート対象データ

### 4.1 1セットの定義

Phase B 既存の `plan_history` エントリ1件と同義:

```text
{
  id,              # 候補セット番号（表示上 #N）
  slots,           # budget / time_slot / area / mood / avoid_areas
  slots_summary,   # 表示用要約文字列
  plans,           # [{ plan, reason }, ...] 最大3件想定
  created_at       # Unix epoch（秒）
}
```

- **含める**: `slots_summary`（または同等の条件要約）、`plans` の案・理由、セット番号 `id`、日時（人間可読）
- **含めない**: `messages`、Gemini 生出力、セッション ID、API キー

### 4.2 ユーザーが選ぶ単位

- **候補履歴**の各セットに **エクスポート** ボタンを1つ（セットごとに独立）
- **結果画面（ResultsView）** にも、**いま表示中の案3つセット** 用のエクスポートボタンを1つ  
  - 結果表示時点では当該セットは既に `plan_history` に追加済みのため、実体は「最新追加セット」と一致する想定

---

## 5. 整形テキスト仕様（コピー本文）

固定の挨拶テンプレは設けない。以下の **構造だけ** を満たすプレーンテキスト（UTF-8）。

```text
【デートBot 候補セット #<id>】
<YYYY/MM/DD HH:MM>   ← created_at を JST 表示

■ 条件
<slots_summary 1行>

■ 案1
<plan 本文>
理由: <reason>

■ 案2
…

■ 案3
…
```

ルール:

- 見出しは上記の通り（全角 `■`、案番号は連番）
- `plan` / `reason` が欠けている項目は `（なし）` とする
- `plans` が3件未満のときは **存在する案だけ** 出力
- 改行は LF。行末の余分な空白は trim
- 文字数上限: **8000 文字**（超える場合は案3以降または理由を省略し末尾に `…（長いので省略）` — 実装時に1箇所で切る）

整形ロジックは **サーバーとクライアントのどちらか一方** に置く（実装時決定）。MVP では **サーバーで生成** し、クライアントはコピーとログ API 呼び出しに専念することを推奨（整形の単一正本）。

## 6. エクスポートログ

### 6.1 目的

「いつ・どのセットをエクスポートしたか」を開発・運用時に追えるようにする（二人利用の軽い監査）。

### 6.2 記録タイミング

クリップボードコピーが **成功したあと**、サーバーに1件追加。

### 6.3 保存場所（MVP）

- **セッション状態（インメモリ）** に `export_logs[]` を追加  
- `reset` またはセッション TTL 切れで **ログも消える**（Phase B の他状態と同じ寿命）
- ファイル・DB 永続化は v1 スコープ外

### 6.4 ログ1件のフィールド

| フィールド | 内容 |
|------------|------|
| `exported_at` | Unix epoch（秒） |
| `plan_history_id` | 対象セットの `id` |
| `text_length` | コピーした本文の文字数 |
| `text_sha256` | 本文の SHA-256（hex）。全文保存の代替または併用 |
| `text` | **コピーした整形本文全文**（ユーザー決定: ログを残す） |

秘密情報（`GEMINI_API_KEY`、`APP_PASSWORD`）はログに含めない。

### 6.5 API（実装時）

| Method | Path | 役割 |
|--------|------|------|
| POST | `/api/export/format` | 入力: `{ "plan_history_id": number }` → 出力: `{ "text": "..." }`（認証必須） |
| POST | `/api/export/log` | 入力: `{ "plan_history_id", "text" }` → ログ追加（認証必須）。`text` は format 応答と一致検証してもよい |
| GET | `/api/export/logs` | 任意: 同一セッションのログ一覧（デバッグ用。UI 露出は MVP 不要） |

※ MVP を最小にするなら **format + log を1エンドポイントに統合** してもよい（実装時判断）。要件上は「ログが残る」ことが必須。

## 7. UI 要件

| 要素 | 要件 |
|------|------|
| ボタンラベル | `エクスポート` または `コピー`（実装時に1つに統一） |
| 配置 | 候補履歴各セットのヘッダ付近、結果画面のアクション付近 |
| 操作 | 1クリック → 整形 → クリップボード → トースト/短い文言 |
| プレビュー | なし |
| 編集 | なし |
| ローディング | サーバー整形中は既存ローディング UI を流用可 |

### 7.1 クリップボード失敗時

- HTTPS でない localhost 以外、権限拒否などで `navigator.clipboard` が失敗しうる
- **フォールバック**: 非表示の `<textarea>` に本文を入れ `document.execCommand('copy')` を試行
- それも失敗したらエラーメッセージ表示。**ログは記録しない**（コピー成功時のみ）

---

## 8. セキュリティ・プライバシー

- エクスポート API は **ログインセッション必須**（他ユーザーの履歴は参照不可 — 現状単一プロセス・Cookie セッション）
- ログに載る本文は **ユーザーがコピーしたデート案** のみ。チャットは含めない
- 公開 GitHub にログは出さない（サーバメモリのみ）
- 要件定義書 v1.3 の「個人情報の取り扱いを Bot 機能に含めない」と矛盾しない範囲: **ユーザー自身が選んでコピーする** 行為に限定

---

## 9. 受け入れ条件（ローカル）

1. 候補履歴に2セット以上ある状態で、**各セットのエクスポート** が独立して動く  
2. コピーしたテキストに **条件・案3・理由** が §5 の形式で含まれる（チャット行は含まれない）  
3. コピー成功後、同一セッションの `export_logs` に1件増える（`plan_history_id` が一致）  
4. 未ログインでエクスポート API を叩くと 401  
5. 存在しない `plan_history_id` では 404 または 400  
6. `reset` 後、エクスポートログも消える  

---

## 10. 実装前に詰めた残り（軽量）

以下は product 決定済みだが、**実装チケットに入れる前** に1行でよいので確定推奨:

| # | 論点 | 推奨（本ドキュメントのデフォルト） |
|---|------|-------------------------------------|
| R1 | LINE「B のみ / C まで」未記入 | **コピーのみ** で確定（上記スコープ） |
| R2 | 結果画面にもボタンを付けるか | **付ける**（§4.2） |
| R3 | ログの全文保存 | **`text` 全文 + `text_sha256`**（§6.4） |
| R4 | 整形の正本 | **サーバー**（§5 末尾） |

R1〜R4 をこのまま採用すれば、追加の product 議論なしで実装に入れる。
