## §1 画面レイアウト（スマホ + PC 共通方針）— 合意 v1

### 1.1 ユーザーの声

- 利用の大半が **スマホ**
- **条件チップが見切れる**
- **候補履歴の横幅が合わない**（右に余白ができる）
- （ログイン後）チャットと条件が同時に見えて **ごちゃごちゃ** → §2 と関連

### 1.2 合意した product 決定

| 項目 | 決定 |
|------|------|
| 優先端末 | **iPhone・Android 両方**（主要幅 360〜430px を必須テスト） |
| ゴール | **A + B ハイブリッド**（見た目調整 **＋** タブ／折りたたみで役割分離） |
| PC（2 列） | **2 列同時表示はやめる**。スマホ同様 **「一画面に主役は 1 つ」** → **タブまたは折りたたみ**でチャット／条件を切り替え |
| 履歴 | **タブ下に常時**。長くなったら **折りたたみ**（一部表示 → ボタンで全件）→ §1.9 |

### 1.3 A パート（見た目・レイアウト調整）

| ID | 要件 |
|----|------|
| A1 | **横スクロール禁止**（意図したチップ横スクロール領域を除く） |
| A2 | **条件チップ**が見切れない：折り返し **または** 1 行横スクロール＋左右 padding で端が切れない |
| A3 | **候補履歴**が親幅いっぱいに揃う（右余白・はみ出し・box-sizing 起因を解消） |
| A4 | 主要ボタン（送る・条件を反映・コピー・条件変更）の **タップ領域 ≥ 44px** 相当 |
| A5 | `viewport`・セーフエリア（`env(safe-area-inset-*)`）でノッチ端末でも余白が破綻しない |
| A6 | キーボード表示時、**チャット入力**が完全に隠れない（可能な範囲で `visualViewport` または scrollIntoView）— 実装難度が高い場合は v1.1 に回す |

### 1.4 B パート（タブ／折りたたみ — PC・スマホ共通）

**原則:** ログイン後のメイン画面で、**チャットと条件パネルを同時に「フル表示」しない**。

| ID | 要件 |
|----|------|
| B1 | **切替 UI** を 1 つ設ける（**タブ推奨**、折りたたみは代替可） |
| B2 | タブ例（ラベルは実装時に調整可）：**「おしゃべり」｜「条件を選ぶ」** |
| B3 | 表示中タブだけ **フル幅** で表示。非表示タブのパネルは **DOM 上は保持してよい**（slots 状態維持） |
| B4 | **候補履歴**はタブ領域の **下に常時** 配置（第 3 タブは使わない）。横幅は A3 |
| B5 | **900px 以上（PC 幅）でも 2 列グリッドに戻さない**（B1〜B3 を維持） |
| B6 | 初回タブは **「おしゃべり」**（§2.2）。画面上部に条件サマリー常時（§2.5） |

### 1.5 ブレークポイント

| 幅 | 挙動 |
|----|------|
| すべて | B1〜B5（タブ／単一主役） |
| ≤ 430px | A1〜A5 を重点テスト（iPhone / 一般 Android） |
| 431px 〜 | タブ UI 維持、余白・フォントは `clamp` で拡大 |

（旧 `@media (max-width: 900px)` の **1 列化だけ** に頼らない。）

### 1.6 受け入れ条件（§1 完了の定義）

1. iPhone Safari・Android Chrome（または DevTools 390×844 / 360×800）で **条件チップが端で欠けない**  
2. 候補履歴カードが **画面幅と揃い**、右だけ空く現象がない  
3. PC 幅（≥1280px）でも **チャットと条件が同時 2 列にならない**  
4. タブ切替でチャット送信・条件反映が **従来どおり動く**（API 変更なし）  
5. 結果画面・コピー・ログインは **既存 Phase B + export v1** を退行しない  
6. 履歴が折りたたみ閾値を超えたとき **一部のみ表示**、「すべて見る」で **全セット展開**（§1.9）  

### 1.9 候補履歴 — 折りたたみ（合意 v1）

| ID | 要件 |
|----|------|
| H1 | 履歴ブロックは **タブ（おしゃべり｜条件）の下** に常時表示 |
| H2 | **折りたたみ前**も **最新 1 セット** は常に見える（0 件時は既存の empty 文言） |
| H3 | セット数が **3 件超**（実装時に定数 `HISTORY_COLLAPSE_AFTER=3` 可）→ **古いセットを畳む**。表示は **新しい順・最大 2 セット** まで |
| H4 | **「すべての履歴を見る」** ボタン（折りたたみ時のみ）→ タップで **全セット表示**。**「たたむ」** で H3 状態に戻す |
| H5 | 各セットの **コピー** ボタンは折りたたみ状態でも **表示中セット** で使える |
| H6 | 展開／折りたたみは **クライアント UI のみ**（API・`plan_history` 構造は変更しない） |

### 1.7 スコープ外（§1）

- 案 3 つを出す **必須スロットルール** の変更 → §3  
- ログイン後の **最初の 1 文ガイド** の文言 → §2  
- 新 API・DB

## §2 ログイン後のごちゃつき・初回体験 — 合意 v1

### 2.1 ユーザーの声

- ログイン後、チャットと条件が同時にあり **何をすればいいかわからない**
- **Bot として** 二人のデートを **全力サポート** してほしい（最近の AI チャットのような挨拶）

### 2.2 合意した product 決定

| 項目 | 決定 |
|------|------|
| 最初のタブ | **A: 「おしゃべり」** |
| 画面上部 | **「いまの条件」サマリーを常時表示**（§2.5） |
| 挨拶・ガイド | **おしゃべり欄の Bot 第一声のみ**（タブ外・バナーでは出さない） |
| Bot 初回 | **AI チャット風**（短い吹き出し・フランク・サポート感） |

### 2.3 画面上部 — 条件サマリー常時

| ID | 要件 |
|----|------|
| S1 | メイン画面（`view-main`）の **タブより上** に **スティッキーまたは固定ヘッダ下** で 1 行表示 |
| S2 | 内容は既存 `slots_summary` と同義（未設定時: **「まだ条件なし — 条件タブかおしゃべりで決めよう」**） |
| S3 | 条件更新・reset 後も **即反映** |
| S4 | 結果画面（`view-results`）では既存の `results-slots` を維持（重複しすぎないレイアウト） |

### 2.4 時刻別の一言（JST）

クライアントまたはサーバーで **ログイン成功時** に 1 つ選択。境界は v1 固定:

| 帯 | 時刻（JST） | 一言（例・文言は実装時に微調整可） |
|----|-------------|-------------------------------------|
| 朝 | 05:00 — 10:59 | 今日が素敵な一日になるように！ |
| 昼 | 11:00 — 16:59 | 昼ごはん食べた？ |
| 夕方〜夜 | 17:00 — 23:59 | 今日もお疲れ様！ |
| 深夜 | 00:00 — 04:59 | 遅くまでお疲れ様！（または 今日もお疲れ様！） |

### 2.5 おしゃべり第一声（ウェルカム = チャット先頭の Bot 発言）

**原則:** 時刻挨拶・使い方・サポート宣言は **すべて「おしゃべり」ログ内の Bot メッセージ** とする。画面上部（§2.3）は **条件サマリーのみ**。別パネルの「ガイド 1 行」は **設けない**。

**タイミング:** ログイン成功後、**`messages` が空** のとき **1 回だけ** `role: bot` を append（**reset 後** も messages 空なら再挿入）。

**文面構成（固定: Bot 吹き出し 2 個）:**

| 順 | 吹き出し | 内容 |
|----|----------|------|
| 1 | **挨拶** | **時刻別一言のみ**（§2.4） |
| 2 | **使い方 + サポート** | 「次のデートプランを一緒に考えよ！ **条件を選ぶ** タブか、この **おしゃべり** で希望を書いてね。」＋ 改行または続けて「ふたりのデート、全力でサポートするからね。」 |

`messages` には **`role: bot` を 2 件** 連続 append（ユーザー発言の前）。

**表示:** デフォルトタブ **おしゃべり** の **`chat-log` 最上段**（ユーザー発言より前）。ログイン直後ユーザーがスクロールしなくても **第一声が見える** 位置。

**AI チャット風 UX:**

| ID | 要件 |
|----|------|
| W1 | **Bot アイコン＋名前**（既存 LINE 風）で第一声を表示 |
| W2 | ウェルカムは **必ず Bot 吹き出し 2 個**（挨拶 / 使い方+サポート） |
| W3 | 初回挨拶に **typing / ハートローディングは使わない**（即表示） |
| W4 | 文言は **テンプレ＋時刻分岐**（Gemini 挨拶は v1 不使用） |
| W5 | 挨拶を **タブ外・トースト・バナー** に出さない |

**実装:** ログイン（および reset 後の空 messages）時に **サーバー** で `messages` に append。時刻は **`Asia/Tokyo`**。

### 2.6 受け入れ条件（§2 完了の定義）

1. ログイン後 **デフォルトタブ = おしゃべり**  
2. 画面上部に **条件サマリー** が常時見える  
3. 初回ログインで **おしゃべり欄の先頭** に **Bot 吹き出しが 2 つ**（挨拶 → 使い方+サポート）がこの順で見える  
4. 2 回目以降（同一セッション・messages あり）で **ウェルカムを重ねない**  
5. reset 後、再びウェルカム（空 messages）  

### 2.7 スコープ外（§2）

- ストリーミング文字送り  
- Gemini による毎回違う挨拶  
- プッシュ通知

## §3 部分入力（場所だけ・予算未定・やりたいことだけ）— 合意 v1

### 3.1 ユーザーの声

- **場所だけ**（例: 渋谷）でも使いたい  
- **予算未定**のまま進めたい  
- **やりたいことだけ**（例: カフェ寄り）でも使いたい  

### 3.2 現行（Phase B）との差分

| 項目 | 現行 | Phase D v1 |
|------|------|------------|
| 案 3 つを出す条件 | `time_slot` **と** `area` 必須 | **緩和**（§3.4） |
| 予算未指定 | 内部 **3000 円** 扱い、表示も 3000 寄り | 表示・案文で **「予算未定」明示**（§3.5） |
| mood のみ | 不足扱いで聞き返し | **優先エリアで仮案 3 つ**（§3.6） |

### 3.3 合意した product 決定（チェックリスト回答）

| # | 質問 | 決定 |
|---|------|------|
| 1 | 場所だけ → 案を出す？聞き返す？ | **案を出してよい**（時間帯がなくても可） |
| 2 | 予算未定 | **「予算未定」と明示した案**を出す（3000 円を決め打ち表示しない） |
| 3 | やりたいことだけ（エリア・時間なし） | **優先エリアで仮案 3 つまで OK** |

### 3.4 案 3 つを出す条件（新ルール）

**原則:** 漠然入力でも **可能な限り案を出す**。情報がほぼ無いときだけ聞き返す。

| slots の状態 | 挙動 |
|--------------|------|
| **`area` あり**（`time_slot` なし可） | **案 3 つを出す** |
| **`mood` のみ**（`area`・`time_slot` なし） | **優先エリア起点の仮案 3 つ**（§3.6） |
| **`time_slot` のみ**（`area` なし） | **優先エリア起点の仮案 3 つ**（mood のみと同様の扱い） |
| **`budget` のみ**（`area`・`mood`・`time_slot` なし） | **優先エリア起点の仮案 3 つ**（指定予算を案・理由に反映） |
| **`area` + `mood` など** | 案 3 つ（従来どおり。時間帯は任意） |
| **avoid だけ** 等、上記いずれにも当てはまらない | **聞き返し**（定型 or Gemini 短い Clarify） |

**聞き返し必須から外す:** `time_slot`（時間帯は **任意**）。

**実装メモ:** `missing_slots()` の必須リストから **`time_slot` を外す**。`area` 単独で提案可。`mood` / `time_slot` のみの経路は **提案モード = 仮案**（§3.6）。

### 3.5 予算（budget）

| ID | 要件 |
|----|------|
| B1 | `budget` が slots に **無い** とき、画面上部サマリー・履歴・結果画面は **「予算未定」** と表示（`3000` を表示しない） |
| B2 | 案 3 つの本文・理由に **予算が未確定** であることが分かる表現を入れる（例: 「予算未定だけど、だいたいコスパ重視で…」） |
| B3 | Gemini プロンプト: 未指定時は **3000 円をユーザーに決めつけた文案にしない**。「予算未定」を優先。内部目安 3000 は **理由文の「学生目安」程度** に留めてよい（完全非表示でも可） |
| B4 | 条件パネルに **予算「未定」** チップまたは未選択＝未定を **明示可能**（任意 UI。未実装なら B1〜B3 のみでも可） |
| B5 | ユーザーが **数値予算を指定した後** は従来どおりその金額を表示 |

**`setdefault("budget", 3000)` を案生成直前に行う現行処理は見直す**（表示と文案が「予算未定」と矛盾しないように）。

### 3.6 優先エリア・仮案（mood / time のみ）

| ID | 要件 |
|----|------|
| P1 | **優先エリア** = 好み要約どおり **渋谷・上野・新宿・お台場・品川**（[date_bot_preferences_summary.md](./date_bot_preferences_summary.md) と整合） |
| P2 | `area` が無いとき、Gemini（またはフォールバック）に **3 案を別エリア寄り** で出させる（同一エリア 3 つに偏らないよう促す） |
| P3 | Bot の短い前置き or 案頭に **「仮の案」** ニュアンス（例: 「エリアまだ決めてなくても、人気エリアで 3 パターン出したよ」）— **1 吹き出し** でよい |
| P4 | 仮案も **候補履歴・コピー** の対象（通常セットと同じ） |
| P5 | 後から `area` / `time_slot` を足したら **通常どおり上書きマージ**（現行 slots マージ維持） |

### 3.7 Gemini / エンジン

| ID | 要件 |
|----|------|
| G1 | `need_clarify` は **§3.4 の「聞き返し」行** に該当するときのみ true |
| G2 | JSON スキーマのルール文を Phase D に合わせて更新（時間帯必須削除、予算未定文案） |
| G3 | フォールバック 3 案も **予算未定・仮案** ラベルに対応 |

### 3.8 受け入れ条件（§3 完了の定義）

1. **「渋谷だけ」**（チャット or 条件）→ **時間帯なしで案 3 つ**  
2. **予算未指定** → サマリー **「予算未定」**、案に **3000 円決め打ちの見出しがない**  
3. **「カフェ寄り」だけ** → **3 エリア相当の仮案 3 つ**（または 3 案にエリア差が分かる）  
4. **予算チップだけ**（例: 5000 円のみ）→ **仮案 3 つ**（聞き返ししない）  
5. **何も無い** 入力 → 聞き返し（案を出さない）  
6. §1・§2 の UI 変更後も上記が **退行しない**  

### 3.9 スコープ外（§3）

- ユーザーが「予算未定」と言ったのに **勝手に 5000 円** 等を slots に書き込む  
- 店舗のリアルタイム価格  
- 複数エリアを 1 案にまたぐ **最適ルート** 計算  

### 3.10 Phase D 実装順（推奨）

1. §3 バックエンド（`missing_slots` / Gemini プロンプト / 予算表示）  
2. §2 ウェルカム 2 吹き出し  
3. §1 タブ + レイアウト + 履歴折りたたみ  

（UI なしでも §3 は API テスト可能。）
